# Crit 10 reflection

## What was the breakthrough that moved the work forward?

The breakthrough was seeing that multi-user rules are part of the user experience, not just security. I could have treated them as a list of things to block. Instead, every rule started from the question "what would make this go smoothly for the person on the other side?" A host can cancel, but the people who joined still see the cancelled Vybe, so nobody turns up to an empty court. The chat is only for the people going, and it stays open after a cancel so they can sort out another day. Once I framed each rule that way, the server checks and the ADR came out of decisions I had already made for the user, and the two-person test from the live URL showed that two people could use it side by side without stepping on each other.

## What did this work change about who I want to be as a software developer?

My rule for every choice is that it has to be better for the user, something the app can actually do, and logic that holds up. This week I used it on every feature: the chat exists because it helps a Vybe go well, not because apps usually have one, and it disappears when the Vybe ends because there's no reason to keep it. Working with the agent, my job was less about writing code and more about deciding what the user should experience and checking that the result matched. I want to be a product manager who starts from the user's path through the product and makes every rule serve it, and who can still explain why each decision holds up.
