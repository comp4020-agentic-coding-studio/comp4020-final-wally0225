# Process overview

This is how Vybe got from the brief to the app deployed at [comp4020-final-wally0225.fly.dev](https://comp4020-final-wally0225.fly.dev/), as of week 11. People sign up, post Vybes (what, where, when, how many) and join them. Every change shows live on everyone else's page, and every Vybe is on a map. People also belong to groups, each Vybe has a chat for the people going, and the server decides who can see and change what, and logs who did it. I rewrite this file at each crit.

## Where the idea came from

Vybe started last semester as a group pitch in another course. I had the initial idea, completed with the group. The pitch was a city-wide platform with profiles, AI recommendation, reputation scores and venue partnerships. This brief asks for small, so I kept the core and dropped everything that was there to grow a business. I chose ANU students because I'm one, my pod is, and so is the showcase audience.

## Choosing the stack

Astro in server mode with SQLite (through Drizzle) on the Fly volume, the stack I shipped in crit 7 ([`0226dd0`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/0226dd0)). Knowing how it deploys meant my effort went into what good means, not tooling. I looked at Hono with `ws` and at SvelteKit; both meant learning a framework in the same week as deciding what the app is for.

In week 9 I named real-time as the risk: I'd switch if Astro's server-sent events didn't hold. They held ([`24ec588`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/24ec588)). Updates only flow from the server to people watching, so I didn't need WebSockets. Because Vybe runs on one machine, the server keeps every open page in memory; a second machine would need a shared channel. For the map I used Leaflet with OpenStreetMap tiles: free, no API key, and nothing about users goes to a third party.

## How I worked with the agent

I make the product decisions; the agent proposes options, builds them and tests them. I agree a plan before any code, then one behaviour per commit. When the agent asked me to pick from four concurrency decisions, I stopped it and asked for explanations first, then decided all four. The one I'll defend is who sees whom: a count of others looking, never who ([docs/decisions/0001-viewer-count.md](docs/decisions/0001-viewer-count.md)). The agent read my README's "nobody sees who looked" as ruling that out; I corrected it, "who" means names, and reworded the README to say so.

For the map, I answered the agent's questions before it planned: the host taps the spot when posting, because "where" in words can't be put on a map. When the agent suggested keeping your location on your phone, I agreed, so the server sends the same list to everyone and the page sorts it, which keeps "what you do on the list stays private" true.

For crit 10, the biggest change of mind was the chat. My README said "no chat", because the big group chat is what Vybe replaces. I changed that once I could say why this one is different: only the people going can use it, it's there to sort out a problem before you meet, and its messages are deleted when the Vybe ends ([`9cbe94a`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/9cbe94a)). The other crit 10 rules, such as only the host cancels and a group's Vybes show to everyone but only members can join, are in [docs/decisions/0002-who-can-see-and-change-what.md](docs/decisions/0002-who-can-see-and-change-what.md), each checked on the server.

Since then I asked for three more changes. The host can edit a Vybe until it starts ([`2233681`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/2233681)), with a size that can't drop below the people already going. There is a light/dark toggle ([`12992c3`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/12992c3)). And everyone now signs up and logs in with a username and a password ([`0abe9a3`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/0abe9a3)). This reverses my earlier "just a first name" decision in ADR 0002, because with an account it's easier to manage user information, so that I can add more features for users in the future, like their preferred tags of Vybes, to make Vybe more personal. Since account exist, user can sign back in on another phone, and each name is unique.

## Checking and correcting the work

The first claim I tested was "full means full" ([`88946dd`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/88946dd)): six people race for two spots and exactly two get in. We removed the capacity rule on purpose, saw the test fail, and put it back.

Since then I write checks before code, so each starts red: live updates ([`cdee7fc`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/cdee7fc) → [`24ec588`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/24ec588)), the chat being only for the people going ([`3a2c357`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/3a2c357) → [`9cbe94a`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/9cbe94a)), and editing ([`4e75919`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/4e75919) → [`2233681`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/2233681)). One correction landed in `spec/`: checks run in parallel, so another check's post could make the live-update check pass with nothing working. Now the update has to name the Vybe that changed. Every check runs against a throwaway database, never the live one.

The checks only see the server, so the agent drove headless Chrome at phone and laptop widths and I reviewed the screenshots. That caught things the checks couldn't: Vybes at the same spot hiding each other, now one numbered pin, and the popup's padding hiding the Join button ([`66df792`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-wally0225/commit/66df792)). The same check caught the dark-mode toggle clipped off a phone's edge, and I had it fixed before merging. I also tested live with a normal and a private window as two people, in separate Chrome profiles.

The corrections now live in the harness. `CLAUDE.md` holds my rule for every choice (better for the user, something the app can actually do, logic that holds up), what the app must never do, and two corrections: explain options before asking me to choose, and check the page in a browser because the checks can't see it.

## Who did what, in the logs

Every action is logged on the server as one line in `flyctl logs`: `[vybe] Ana(4a8cb473) join invite=12 result="joined"`. A person is their username and the start of their id. Refusals are logged with why (`result="not-owner"`), so a refused attempt never reads as success; the agent first logged a refused promotion as "made host", and we changed it to "make host" with its result. Chat lines say who wrote and how long it was, never what it said, and login lines never include the password.
